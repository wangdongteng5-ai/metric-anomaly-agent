# 策略手册（v1，10-08 Morgan 确认）

> 用途：search_playbook 按标题切段检索，模型写方案说明时引用。硬数字以 `code\project\playbook.yaml` 为准，本文只解释"为什么"。
> 数据：84.51° Complete Journey（美国连锁超市）；业务表述按即时零售 / 生鲜电商。

## 通用规则
- Agent 只出方案，**不执行**；所有方案须运营人工确认后才发放。
- 排除疲劳用户：被触达 ≥ 5 个活动且从未核销的家庭不再触达（数据无退订字段，用此近似；实测 373 户，占 15.1%）。
- 频控：每户每月最多被 2 个活动触达。实测多数月份同时 ≥ 3 个活动的户 ≤ 2%，旺季（11～12 月）达 17%～20%。
- 用户侧动作分两类手段：**主手段**是发券（数据里有历史核销记录，能估算人数、成本、影响）；**备选手段**只给文字建议，标注"无历史数据，不估算"，由运营判断。
- 预期影响给区间，不给单个数：保守按 Type B 核销率 6.5%，乐观按 Type A 16.6%。核销率是历史相关数据，不代表因果效果，真实效果要靠实验验证。

## 召回流失家庭
- 适用：主因是某分组的**户数**下跌（人没来）。
- 圈人：前 28 天在该分组买过、本周没有购买的家庭。28 天来自购物间隔分布（95 分位 21 天、99 分位 51 天）。
- 为什么不用更窄的定义：本周没来的人里 43%～49% 下周会自己回来；改成"连续 2 周没来"会漏掉刚流失的人（S01 实测只圈到 18/72），改成"每周都来的断了"自己回来的反而更多（71%～76%）。只看一周分不出真流失，所以名单保持完整，浪费用对照组量化。
- 用券户 GMV 不是增量：用券的人里有一部分本来就会回来，真实增量要留对照组验证。
- 权益（主手段，估算影响）：回归券 满 18 减 1。
- 备选手段（无历史数据，不估算）：免配送费 1 次｜push 提醒常购商品到货。
- 注意：流失原因可能是竞品分流或服务问题，券只能挽回价格敏感的那部分。

## 提升频次
- 适用：主因是**频次**下跌（来得少了），户数基本不变。
- 圈人：本周来过、本周购物篮数低于自己前 4 周周均的家庭。
- 权益（主手段，估算影响）：4 周内再来 2 次，返 1 美元券。
- 备选手段（无历史数据，不估算）：会员连续下单任务（如每周下单得积分）｜按购物间隔在预计补货日 push 提醒。
- 注意：频次下跌常与配送体验、活动结束有关，先看同期是否有活动刚结束（若有，优先考虑补券）。

## 提升客单价
- 适用：主因是**客单价**下跌（买得少了），订单数不变。
- 圈人：本周来过、本周客单价低于自己前 4 周客单价的家庭。
- 权益（主手段，估算影响）：满额减 1 美元，门槛设为该组前 4 周客单价中位数 × 1.2，引导凑单。
- 备选手段（无历史数据，不估算）：满赠 / 加价购｜购物车页凑单推荐。
- 注意：客单价易被个别大单影响，下结论前确认不是上周有异常大单。

## 补券
- 适用：主因在 **camp（活动触达）** 维度，即被某个已结束活动触达的家庭订单下降。
- 圈人：被该活动触达过、本周购物篮数低于自己前 4 周周均的家庭。
- 权益（主手段，估算影响）：补发该活动同类券 1 张。
- 备选手段（无历史数据，不估算）：push 告知新一期活动上线时间。
- 核销率：优先用该活动自己的历史核销率。

## 排查商品
- 适用：主因在商品维度（品类 / 细分品类），或提问范围本身是品类。
- 输出：提问范围内 GMV 变化额最负的细分品类 / 商品 Top 20，交品类运营排查缺货、价格、下架。
- 不圈人、不发券。

## 修数据
- 适用：数据质量检查超线（无效行占比 > 2%｜整周变 0 的门店占上周 GMV > 5%｜连续 ≥ 2 天日 GMV 环比跌超 30%），且不在节假日表内。
- 输出：超线检查项、涉及日期 / 门店、影响的 GMV，交数据团队。
- 数据修好前，不对这一周做业务归因。

## 不行动
- 适用：节假日表内的周、召回 0 个候选，或所有候选被复核排除。
- 输出：说明为何判正常波动，列出依据（例如"上周含月初，月初后一周常回落 9%～11%"）。
